## 1. Replace unrestricted executor access

Audit these generic families and every alias/re-export:

- `query`
- `getOne`
- `getMany`
- transaction query callbacks
- pool/client direct query wrappers
- SQL-file execution helpers

Production HTTP handlers and production-reachable services must not be able to pass arbitrary SQL strings into a generic executor.

Introduce a narrow query-descriptor or registered-query boundary consistent with the repository’s existing patterns.

A valid production query must be one of:

- an immutable static SQL descriptor;
- a registered fixed query ID;
- a descriptor produced by a reviewed finite query builder;
- a migration/tool descriptor that is provably unreachable from production runtime.

Each descriptor must separately carry:

- immutable SQL text;
- bound values;
- query identity;
- operation type;
- permitted execution context.

Reject plain strings at the production-facing boundary unless they originate from an explicitly isolated, non-production-only tool.

Do not depend only on TypeScript/JSDoc or comments. Enforce the boundary at runtime.
