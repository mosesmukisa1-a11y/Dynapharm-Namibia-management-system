# **1. FIX BRANCH STOCK RECEIVING WORKFLOW**

## **Current problem**

The workflow for receiving stock in branches is not accepting receipt properly.

## **Required correction**

Fix the branch receiving workflow so that branch users can successfully receive approved stock.

### The receive action must:

1. Open only for dispatches already approved by GM
2. Be available only to the **destination branch**
3. Allow the destination branch to:

   * open dispatch details
   * confirm receipt
   * add received notes
   * e-sign
   * report discrepancies
4. Save successfully without freezing or rejecting valid receipts
5. Update status correctly after submission

### Required statuses

Use clear states such as:

* Pending GM Approval
* Approved
* Awaiting Branch Receipt
* Partially Received
* Received
* Discrepancy Reported

---

# **2. ENSURE ONLY THE DESTINATION BRANCH CAN SEE AND RECEIVE STOCK**

This is critical.

## **Required rule**

Stock dispatched to branches must be visible and receivable **only by the destination branch**.

### Example

If stock is dispatched to **Oshakati**, it must:

* appear only on the Oshakati branch dashboard
* not appear on Ondangwa, Rundu, Tsumeb, or any other branch dashboard
* only allow receipt action by Oshakati branch users

## **Implementation requirement**

Filter incoming dispatches strictly by:

* destination branch ID
* destination branch name
* user role / branch assignment

No other branch should see, confirm, reject, or edit that dispatch.

---

# **3. CREATE A FULL “DISPATCH NOTE” DOCUMENT**

Every warehouse-to-branch dispatch must prepare a full document named:

# **DISPATCH NOTE**

This must not be just a small summary card.
It must be a proper printable business document.

## **Dispatch Note must include full stock details**

At all times, stock details must show in full:

* Product name
* Batch number
* Expiry date
* Quantity dispatched
* Unit where applicable
* Source warehouse
* Destination branch
* Dispatch reference number
* Dispatch date
* Prepared by
* Approval status
* GM approval section
* Branch receipt section
* Notes section
* Barcode

### Expiry date is very important

Do not omit expiry date anywhere in dispatch views, approval views, receiving views, or printed documents.

---

# **4. ADD BARCODE TO DISPATCH NOTE**

Each Dispatch Note must include a barcode.

## **Barcode purpose**

The barcode should represent the dispatch reference number or unique dispatch record ID.

## **Requirements**

1. Barcode must appear on the Dispatch Note PDF and print version
2. Barcode must be readable and well positioned
3. Barcode must also appear in on-screen preview
4. Barcode must remain linked to the dispatch record for lookup if scanning is later added

---

# **5. PDF VIEW AND PRINT FOR DISPATCH NOTE**

The Dispatch Note must support:

* PDF view
* PDF print
* standard print layout

## **Requirements**

1. User must be able to preview the full Dispatch Note before printing
2. The PDF version must show the complete document, not a cut-off summary
3. The printed layout must be clean and official
4. Product lines must display:

   * product name
   * batch
   * expiry date
   * quantity
5. Dispatch note should be suitable for warehouse, GM, and branch operational use

---

# **6. BRANCH CONFIRMATION BY E-SIGNATURE OR NOTES**

When the branch receives stock, the branch user should be able to confirm receipt in either or both of these ways:

## **A. E-signature**

Allow the branch receiving user to e-sign when confirming receipt.

### E-sign may be:

* typed signature name
* digital signature pad if already supported
* saved sign-off confirmation tied to user identity

## **B. Notes / discrepancy capture**

Allow the branch receiving user to add notes when what was dispatched does not match what was received.

### Examples of notes:

* quantity short received
* damaged stock
* missing item
* wrong batch
* near expiry
* wrong product line

## **Required result**

The receipt workflow must support:

* full receipt with sign-off
* discrepancy receipt with notes
* partial receipt if business logic allows

---

# **7. HANDLE DISPATCH MISMATCH / DISCREPANCY PROPERLY**

If the dispatch does not match what the branch receives, the system must not force a false full receipt.

## **Required correction**

Allow branch to record discrepancy against the Dispatch Note.

### Branch should be able to:

* confirm item-by-item receipt if possible
* record mismatch notes
* mark receipt as discrepancy reported or partially received
* submit the receipt with notes and signature

## **System response**

1. Keep a discrepancy log
2. Notify relevant users
3. Preserve document history
4. Prevent silent inventory corruption

---

# **8. GM APPROVES A FULL DOCUMENT, NOT JUST A BUTTON ACTION**

The GM must approve a **full Dispatch Note document**, not only a small action row.

## **Required GM approval screen**

The GM approval view must display the full Dispatch Note including:

* dispatch reference
* source warehouse
* destination branch
* product name
* batch
* expiry date
* quantity
* prepared by
* date
* notes
* barcode
* linked PDF preview where possible

The GM must clearly see the exact full document being approved.

---

# **9. GM MUST BE ABLE TO AMEND THE DISPATCH NOTE**

The GM must not only approve or reject.
The GM must also be able to **amend** the Dispatch Note before approval.

## **Examples of amendment**

* reduce quantity
* remove wrong item
* correct wrong batch
* return dispatch for correction
* adjust note
* partially approve lines if your structure supports line-level changes

## **Required actions**

GM actions should include:

* Approve
* Reject
* Amend and Approve
* Return for Correction

---

# **10. IF GM AMENDS, AUTHOR MUST BE NOTIFIED**

If the GM amends the document, the author / preparer must be notified.

## **Author means**

The user who created the dispatch from the warehouse.

## **Required notification**

The author should be notified with:

* dispatch reference number
* what was amended
* original values
* approved amended values
* GM comment / reason
* timestamp

## **Notification destinations**

Show this in:

* warehouse dispatch history
* notification center if available
* dispatch record audit log

---

# **11. STOCK LEVELS MUST ADJUST AUTOMATICALLY AFTER GM AMENDMENT**

This is critical.

If the GM amends the Dispatch Note, stock levels must be adjusted correctly before the branch receives stock.

## **Examples**

### Example 1

Warehouse prepared 20 units, GM amends to 15 units:

* reserved / pending dispatch quantity must become 15
* 5 units must return to available warehouse stock

### Example 2

Wrong batch removed:

* removed batch quantity must restore to warehouse available stock
* approved batch remains pending for branch receipt

## **Required rule**

GM-approved final document is the authoritative quantity for the receiving stage.

Branch must only see the final approved amended stock quantities.
