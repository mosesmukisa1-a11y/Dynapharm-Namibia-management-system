
# 🚨 GM PORTAL — PORTAL-SOURCE ANALYSIS + EXACT API SCRIPT

## Purpose

The **GM portal** must be a **management decision portal**, not a separate calculation engine.

It must consume live data from:

* stock engine
* sales engine
* reporting engine
* finance-ready summaries
* branch performance summaries

It must not calculate its own totals independently.

## GM portal must receive stock information from

* `stock_movements`
* `inventory_balances`
* `branch_summary_view`
* `warehouse_summary_view`
* `company_stock_summary_view`
* `stock_alerts_view`

## GM portal must receive sales information from

* `sales_transactions`
* `sales_summary_view`
* `branch_sales_summary_view`
* `prescription_dispense_sales_view`
* `consultation_fee_summary_view`

---

### 1. Company stock overview

Must show:

* total company stock qty
* total company stock DP value
* total warehouses stock
* total branch stock
* in-transit stock
* low stock items
* expiring items

### 2. Branch performance overview

Must show per branch:

* closing stock
* stock value DP
* sales units
* sales revenue
* dispensed units
* low stock count
* expiry risk count
* write-off qty/value

### 3. Warehouse overview

Must show:

* Windhoek stock summary

* dispatch activity
* stock value
* expiry risk
* low stock

### 4. Sales category summary

Must show:

* consultation fees
* walk-in sales
* member sales
* non-member sales
* online fulfilled sales
* prescription dispensing sales
* total sales

### 5. Profitability / operational view

Must show:

* DP stock value
* sales totals
* branch performance ranking
* top products by movement
* slow/fast-moving products if available

# 🚨 MIS PORTAL — PORTAL-SOURCE ANALYSIS + EXACT API SCRIPT

MIS must consume:

* branch sales records
* branch stock movement totals
* product-wise quantities
* distributor-linked sales if applicable

MIS must not use disconnected manually re-entered figures where the system already has them.

## MIS service requirements

### Suggested services

* `misReconciliationService.ts`
* `branchProductReconciliationService.ts`
* `encodedSalesComparisonService.ts`

### Core reconciliation formulas

#### Branch-level

```text
expected_closing = opening + received + transfer_in + return_in - sold - dispensed - transfer_out - write_off
mismatch_qty = actual_closing - expected_closing
```

#### Sales-level

```text
sales_difference = live_sales_value - encoded_sales_value
```

#### Product-level

```text
product_mismatch = movement_outward_qty - (sold_qty + dispensed_qty + writeoff_qty + transfer_out_qty)
```

# 🚨 SHARED IMPLEMENTATION RULES FOR GM, FINANCE, MIS

## 1. Shared engines required

Replit must ensure these portals read from:

* `stockEngine`
* `salesEngine`
* `reportingEngine`

## 2. No duplicate formulas

GM, Finance, and MIS must not each calculate stock differently.

## 3. DP rule

All internal stock values must use DP.

## 4. Posted transactions only

Only completed/posted movements and completed/posted sales must feed these portals.

## 5. Prescription rule

Only actually dispensed quantities and actual prescription sales may flow into these portals.

## 6. Blank field rule

If values are zero/blank while records exist, fix the binding source, not the UI.
