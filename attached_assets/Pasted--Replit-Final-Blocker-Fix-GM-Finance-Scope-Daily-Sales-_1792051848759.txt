## Blocker 1: GM and administrator Finance dashboards issue unscoped branch requests

Current failures:

```text
GET /api/branch/walkin-sales?from=...&to=... -> 400
GET /api/branch/deposits?from=...&to=... -> 400
GET /api/branch/expenses?from=...&to=... -> 400
```

Response:

```json
{"success":false,"error":"branch parameter is required"}
```

Known callers:

- `client/src/pages/portals/GMPortal.jsx` — `DashboardTab.loadData`
- `client/src/pages/portals/FinancePortal.jsx` — `DashboardTab`

The server safeguard is intentional. Do not remove or weaken `requiresBranchParam` in `api/_lib/auth.js` or the branch handlers.

### Required correction

For administrative company-wide dashboards, request each authorized branch explicitly and aggregate the successful responses. Reuse the existing authorized branch list/canonical branch IDs already used by the fixed Stock dashboard.

Parameter contracts observed by the release gate:

- Walk-in sales accepts `branch_id=<canonicalBranchId>`.
- Deposits accepts `branch=<canonicalBranchId>`.
- Expenses accepts `branch=<canonicalBranchId>`.

Do not assume these parameter names are interchangeable.

Create/reuse one shared helper so GM and Finance do not independently reimplement branch aggregation.

```ts
type BranchReadSpec<T> = {
  endpoint: string;
  branchParam: "branch" | "branch_id";
  extract: (payload: unknown) => T[];
};

async function readAuthorizedBranches<T>(
  branches: Array<{ id: string; name: string }>,
  spec: BranchReadSpec<T>,
  commonParams: Record<string, string>,
): Promise<{
  rows: T[];
  failures: Array<{ branchId: string; status?: number; message: string }>;
}> {
  const results = await Promise.allSettled(
    branches.map(async (branch) => {
      const params = new URLSearchParams(commonParams);
      params.set(spec.branchParam, branch.id);
      const response = await api.get(`${spec.endpoint}?${params.toString()}`);
      return { branchId: branch.id, rows: spec.extract(response) };
    }),
  );

  const rows: T[] = [];
  const failures: Array<{ branchId: string; status?: number; message: string }> = [];

  results.forEach((result, index) => {
    if (result.status === "fulfilled") {
      rows.push(...result.value.rows);
    } else {
      failures.push({
        branchId: branches[index].id,
        status: result.reason?.status,
        message: result.reason?.message || "Branch data unavailable",
      });
    }
  });

  return { rows, failures };
}
```

Adapt to the project API client and response shapes.

### No false zero rule

The current callers swallow failures into empty arrays, which can present unavailable data as zero. Stop doing that.

If any branch request fails:

- show `Incomplete data` for the affected dashboard section;
- show the number/names of unavailable branches where permitted;
- preserve successful branch results separately;
- do not display a company-wide zero or complete total as though all branches responded;
- provide Retry.

If all branch requests succeed, render the normal aggregate.

### Deduplication

Before aggregating sales or financial rows, deduplicate only by stable persisted identity such as sale ID, receipt ID, deposit ID, or expense ID. Do not deduplicate by amount/name/date alone.

## Blocker 2: Nested interactive controls in DailySalesCard

Known source:

- `client/src/components/DailySalesCard.jsx`

The expandable header is a button and currently contains a nested Refresh button. This is invalid interactive markup and triggers React/browser warnings in GM and Director.

### Required correction

Use a non-interactive wrapper containing sibling controls:

```tsx
<div className="daily-sales-card-header">
  <button
    type="button"
    className="daily-sales-card-toggle"
    aria-expanded={expanded}
    aria-controls="daily-sales-card-content"
    onClick={() => setExpanded((value) => !value)}
  >
    <span>Today's Sales</span>
    <span aria-hidden="true">{expanded ? "−" : "+"}</span>
  </button>

  <button
    type="button"
    className="daily-sales-card-refresh"
    onClick={handleRefresh}
    disabled={loading}
  >
    Refresh
  </button>
</div>
```

Requirements:

- no button inside another button;
- Refresh does not toggle expansion;
- expansion remains keyboard accessible;
- visible focus states remain;
- GM and Director render without nested-button warnings;
- existing sales calculations and API behavior remain unchanged.
