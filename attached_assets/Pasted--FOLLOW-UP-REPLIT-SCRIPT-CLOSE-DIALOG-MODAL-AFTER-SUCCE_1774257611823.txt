* Approve
* Reject
* Amend
* Confirm Receipt
* Submit
* Receive
* Return for Correction

the **dialog / modal does not close** after the action succeeds.

This makes the workflow feel incomplete, even though the backend action is now working.

This must be fixed immediately.

Do **not** remove the working button logic.
Do **not** redesign the workflow again.
This is now a **dialog state handling and UI completion fix**.

---

# 1. MAIN ISSUE TO FIX

## Current behavior

* User clicks action button inside a dialog / modal
* Backend action succeeds
* Status updates correctly
* But the dialog remains open
* User must close it manually or refresh the page

## Correct behavior required

After a successful action:

* the dialog must close automatically
* the parent page must refresh or update
* the new status must be visible immediately
* the next valid interface must appear where applicable

# 3. REQUIRED DIALOG BEHAVIOR AFTER SUCCESS

After a successful submit inside a dialog:

1. Save action successfully
2. Show success feedback
3. Close the dialog automatically
4. Refresh parent data or invalidate query/cache
5. Show updated status on the page
6. Open next interface only where business flow requires it

### Example

* Approve in GM modal → save approval → show “Approved successfully” → close modal → refresh record page / queue → show approved status
* Confirm Receipt in branch modal → save receipt → show success → close modal → refresh branch incoming stock list → move item out of pending receipt
* Reject dialog → save rejection → close modal → record disappears from pending approval queue and shows rejected status

---

# 4. DO NOT CLOSE DIALOG ON FAILURE

Important:

If the action fails, the dialog must **stay open** and show the error clearly.

## Required rule

* **Success** → close dialog
* **Failure** → keep dialog open and show validation / server error

### Example

If batch number is missing or note is required:

* do not close modal
* show error inside dialog
* allow user to correct and resubmit

---

# 5. LIKELY TECHNICAL ISSUE TO FIX

Most likely one of these is happening:

* modal open state is not tied to success callback
* action resolves successfully but `setOpen(false)` is never called
* async submit succeeds but UI state is not updated
* mutation success handler missing
* dialog is controlled but parent state never changes
* success toast appears, but modal close function not triggered
* modal close runs before action completes and gets blocked
* route refresh happens without resetting dialog state
* action is inside form submit but modal component remains mounted with open state still true

---

# 6. REQUIRED IMPLEMENTATION RULE

For every stock action modal, wire the success flow properly.

## Required pattern

After confirmed successful backend response:

* set submitting/loading false
* trigger success message
* close modal/dialog
* refresh page data / list / record detail
* optionally navigate to updated record if needed

### Pseudologic

* submit action
* await backend success
* if success:

  * toast success
  * close dialog
  * refresh/invalidate data
* if error:

  * keep dialog open
  * show error

---

# 7. CHECK BOTH CONTROLLED AND UNCONTROLLED DIALOGS

Replit should inspect whether the modals are using:

* local `open` state
* lifted parent `open` state
* form wrapper with dialog trigger
* headless UI / Radix / shadcn dialog controls
* route-based modals

Then fix accordingly.

## If controlled dialog

Ensure the success handler updates the controlling `open` state to false.

## If parent-controlled dialog

Ensure the parent callback is triggered after mutation success.

## If route-based modal

Ensure successful submit redirects back to parent page and clears modal route state.

---

# 8. REFRESH DATA AFTER CLOSE

Closing the dialog alone is not enough.

After close, the page behind it must reflect the new workflow state.

## Required updates

* invalidate data query
* refresh server component / loader
* re-fetch record list
* update status badge
* move record to next queue if needed
* remove completed item from old queue

### Examples

* approved item leaves GM pending queue
* received item leaves branch pending receipt list
* rejected item leaves pending approval list
* amended item reopens in final approved state

---

# 9. ENSURE LOADING STATE CLEARS PROPERLY

Sometimes the dialog stays open because submitting state never resets.

Check and fix:

* loading spinner never ending
* promise rejection swallowed
* `finally` block missing
* dialog buttons remain disabled after success
* modal remains locked because `isSubmitting` stays true

Required:

* always clear submitting state after success or failure
* do not leave modal frozen
