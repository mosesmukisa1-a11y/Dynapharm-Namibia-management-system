3. REMOVE STARTUP CREDENTIAL SEEDING
==================================================

Remove all production/runtime startup logic that:

- contains plaintext staff passwords;
- creates staff users with fixed passwords;
- resets existing staff passwords;
- updates users from hardcoded arrays;
- silently creates default privileged users;
- prints credentials.

Do not delete genuine users.

Reference/bootstrap data must never include authentication credentials.

If development needs synthetic accounts, place them behind an explicit test-only fixture mechanism that:

- refuses production/deployment markers;
- uses independently generated temporary credentials;
- never commits credential values;
- cannot run from web startup;
- cleans up isolated test data.

Add tests proving production and deployment startup cannot create or reset staff credentials.

==================================================
4. PASSWORD STORAGE
==================================================

Inspect the authentication implementation without reading production password values.

Verify:

- passwords are stored using a modern password hash;
- plaintext passwords are never persisted;
- login compares hashes safely;
- password logs are impossible;
- password reset invalidates prior credentials;
- reset tokens are one-time, short-lived and hashed where stored;
- privileged resets require an authorized actor and audit trail.

If current storage is plaintext or reversibly encrypted, repair it using the project’s established authentication framework and add migration planning. Do not migrate production now.

Do not silently rehash unknown plaintext production values through a normal web request.

7. PASSWORD ROTATION RUNBOOK

Prepare, but do not execute, a production rotation runbook for every affected active account.

The runbook must:

1. Identify affected accounts by safe account ID and username without passwords.
2. Confirm the account owner and role.
3. Generate unique random temporary credentials through a secure mechanism.
4. Never print credentials in shared logs or reports.
5. Deliver credentials privately to the verified account owner.
6. Require password change at first login.
7. Invalidate all old sessions.
8. Verify the old password no longer works.
9. Verify the new temporary password works once.
10. Verify the permanent replacement password works.
11. Record actor, timestamp and audit reference.
12. Provide an emergency rollback that does not restore exposed passwords.
