The **Branch Stock module** must become a real operational stock engine for branch-level activity.

It must track:

* what stock the branch received
* from which warehouse/source
* in which batch
* with which expiry
* how much was received
* how much was sold
* how much was dispensed via prescription
* how much was transferred
* how much was written off
* what remains available
* what movements happened
* what values are attached using DP pricing
* what records must flow into stock reports and finance reports

The Branch Stock area must be one of the cleanest, most detailed, modern, and useful parts of the system.

# 2. TRUE DATA SOURCE RULE

Branch stock must not be manually guessed.

It must be built from real transactions coming from:

* stock received from warehouse
* stock transfers in/out
* write-offs
* walk-in sales
* member sales
* non-member sales
* prescription dispensing sales
* online order fulfilment
* adjustments where valid
* returns if supported

These are the true sources for branch stock balances and movement logs.

# 4. VERY IMPORTANT SALES / REPORTING RULES

## DP ONLY RULE

While generating internal branch sales reports, totals for branch amounts must use **DP prices only**.

This is critical.

Do not use CP or customer price for internal stock and business portal calculations.

### Therefore:

* internal branch stock value = DP
* internal stock movement value = DP
* internal sales report total branch amount = DP
* internal finance basis = DP
* stock prices for internal business reporting are determined by DP

---

# 5. NON-MEMBER SALES RECEIPT RULE

In the case of **non-member sale**:

> the distributor copy of the receipt must look **exactly like the branch copy**

Do not create different receipt layouts or incomplete copies.

Both copies must match in:

* header style
* product listing
* quantities
* prices
* totals
* referral details if applicable
* date
* receipt number

Only labels such as “Branch Copy” / “Distributor Copy” may differ if needed.

---

# 6. PRESCRIPTION DISPENSING RULES

When dispensing prescription sales:

## Receipt behavior

The **sale receipt must only show the dispensed products and amount**.

It must not show products that were prescribed but not dispensed.

Only actually dispensed items should appear on the receipt.

## Prescription record behavior

The client prescription must be saved with dispensing status:

* Not Dispensed
* Partially Dispensed
* Fully Dispensed

### For each prescribed item, system must know:

* prescribed quantity
* dispensed quantity
* balance not yet dispensed
* dispense date
* dispensing staff
* linked sale receipt

### If partially dispensed:

* save remaining undispensed items
* allow future completion
* keep accurate status until fully dispensed

### If fully dispensed:

* mark full prescription as fully dispensed
* update stock movement and sales properly
